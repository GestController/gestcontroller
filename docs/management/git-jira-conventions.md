# Git, GitHub and Jira Conventions

**Version:** 0.1 · **Status:** Draft (GestC01)

## Names in Jira
- **Sprints:** `GestC01 - Scope and management plan` (two-digit code and descriptive name).
- **Task labels:** the sprint code (`GestC01`) and the type (`documentation`, `management`, `infra`, `backend`, `frontend`, `testing`).
- **Keys:** generated by Jira (`SCRUM-n`) and always used in Git.
- **Language:** sprint names, task titles, descriptions and commit messages are written in English.

## Branches
`SCRUM-n-short-description`, for example `SCRUM-5-scope-charter`. The main branch is `main`: everything enters through a pull request.

> **Protecting `main`:** in a GitHub organization on the free plan, branch protection rules and rulesets only apply to **public** repositories. When the repository is made private, that protection stops being enforced. If a higher plan is not purchased, it is kept as a **team agreement**: nobody pushes directly to `main`, every PR gets a review and CI checks must pass before merging.

## Commits
`SCRUM-n short description`, for example: `SCRUM-5 add scope charter`.

## Pull requests
- Title with the key: `SCRUM-5 Scope charter`.
- Short description of what changes and how it was verified.
- At least one review before merging.
- Merge with *squash* to keep the history clean.

## Repository
A single private repository (`gestcontroller`) with code, infrastructure and documentation. CI Actions consume plan minutes: keep workflows lightweight.

## What is never committed
Lab credentials, private keys (`.pem`), `*.tfstate` files, `.env` files with secrets.
Keep a `.gitignore` with these rules from the first commit.
